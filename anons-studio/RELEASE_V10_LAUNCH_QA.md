# Anons Studio v1.0 — предзапусковой контроль

Статус: **Release Candidate / QA**. Коммерческий запуск, реальная продажа и автоматическое списание **не разрешены**.

## Что проверяется автоматически

| Направление | Проверка | Где |
|---|---|---|
| Основной редактор | 18 сочетаний 6 шаблонов × 3 формата, кириллица, PNG и мобильные экраны | `smoke.mjs` |
| Слои и графика | Перетаскивание, порядок, цвета, копии, сохранение, ZIP | `smoke.mjs` |
| Данные пользователя | Сохранение локального JSON и восстановление без разрушения исходного облачного проекта | `smoke.mjs` |
| Авторизация | Формы входа, сброса пароля и ограничение доступа к функциям | `smoke.mjs`, `security.test.mjs` |
| Хранение | История версий, конфликт облачных обновлений, отсутствие потери старого проекта | `smoke.mjs` с макетом БД |
| Биллинг | Актуальный публичный сервер возвращает disabled и запрещает checkout | `live-release-gate.test.mjs` |
| Платный экспорт | Анонимный и поддельный Bearer-токен не дают PNG | `live-release-gate.test.mjs` |
| Личный кабинет | Публичный API не отдаёт историю заказов анонимному пользователю | `live-release-gate.test.mjs` |
| CORS | Посторонний Origin не разрешён | `live-release-gate.test.mjs` |

Публичные тесты **не создают пользователей, платежей, заказов и записей в БД**. Они проверяют только фактическое поведение действующего API. Падение этих проверок блокирует новую публикацию.

## Проверено по реальной базе Supabase 3 ноября 2026 года

- Таблицы `anons_studio_memberships`, `anons_studio_payment_orders`, `anons_studio_projects`, `anons_studio_project_revisions` имеют RLS.
- Для проектов и версий политики дают доступ своему владельцу; для подписок и заказов обычным пользователям открыт только SELECT собственных записей.
- RPC `anons_studio_settle_verified_payment` недоступна ролям `anon` и `authenticated`, но доступна `service_role`.
- Функция `anons_studio_save_project` доступна авторизованному пользователю; тесты реального межпользовательского доступа ещё нужны.
- Предупреждение советника `auth_leaked_password_protection`: необходимо отдельно включить проверку скомпрометированных паролей в Supabase Auth, если тариф/настройки позволяют.
- Другие предупреждения об RLS/SECURITY DEFINER относятся к `reader_*` и требуют **отдельного аудита Hunmeng Novels**; в рамках этого этапа их не меняли.

## Резервные копии JSON

В редакторе доступны кнопки **«Резервная копия JSON»** и **«Восстановить JSON»**. Снимок включает тексты, восемь карточек, оформление и изображение (если загружено). Файл необходимо хранить безопасно: он может содержать личные данные.

Восстановление проверяет версию и размер файла, требует подтверждения и открывает отдельный черновик. Уже открытый облачный проект не перезаписывается. При ошибке синхронизации импорт отменяется. Для резервного копирования по-прежнему работает обычный Free без аккаунта.

## Что нельзя считать проверенным

1. **Реальная доставка писем**, подтверждение адресов, восстановление пароля и вход на двух настоящих устройствах; UI-тесты подменяют ответ сервиса.
2. **Точное соответствие серверного платного PNG и Canvas**: общая геометрия внедрена, но полного визуального сравнения с реальным подписанным тестовым пользователем нет.
3. **Отдельный тестовый магазин ЮKassa**, фискализация, чеки, процесс отмены и возврата, переплат, одновременных заказов, обработка задержанных webhook — ещё не доведены до полноценной проверки.
4. **Юридическая готовность**: реквизиты владельца, политика конфиденциальности, условия использования, условия возврата и соответствие требованиям об обработке персональных данных и их локализации должны пройти профильную проверку.
5. **Поддержка, мониторинг и резервное копирование сервиса**: нужны контактный адрес, обработка ошибок, план восстановления Supabase и регулярное сопровождение.

## Условия допуска к публичному запуску

- [ ] Все автоматические тесты проходят на финальном коммите
- [ ] Два реальных тестовых аккаунта проверяют изоляцию приватных данных
- [ ] Вход, подтверждение email и восстановление пароля протестированы на двух устройствах
- [ ] 18 эталонных PNG визуально проверены против серверного экспорта
- [ ] Все платёжные сценарии испытаны на **отдельном тестовом окружении**
- [ ] Настроены чеки, юридические документы и контакт поддержки
- [ ] Проведена проверка требований персональных данных
- [ ] Владелец отдельно разрешил включить реальные платежи и коммерческий запуск

Не снимать блокировку `LIVE_CHECKOUT_REVIEWED=false` в `anons-billing` без выполнения указанных условий и согласия владельца.
