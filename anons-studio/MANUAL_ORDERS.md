# Anons Studio · выбор тарифа при ручной оплате (тестовая версия)

## Пользовательские номера

- ID-1 **зарезервирован** для владельца. Он не присваивается первому зарегистрировавшемуся автоматически.
- Другие подтверждённые аккаунты получают ID-2, ID-3 и так далее. Каждый номер навсегда связан с UUID пользователя Supabase Auth.
- Номера заказов отдельные: AS-100001, AS-100002… Их нельзя использовать как подтверждение прав на чужой аккаунт.
- Вход и права доступа всегда проверяются по Supabase Auth UUID и RLS, а не по короткому видимому ID.

## Настройка владельца (только после верификации)

Пока владелец не подтвердил, **какой именно аккаунт принадлежит ему**, ID-1 остаётся незанятым; на странице не появится административная панель.

После проверки владельца и его **подтверждённого** адреса электронной почты уполномоченный администратор запускает в панели Supabase SQL Editor транзакцию под привилегированной ролью. Заменить `<VERIFIED_OWNER_AUTH_UUID>` на фактический UUID из Supabase Auth. **Не принимать UUID от произвольного посетителя сайта как доказательство владения.**

```sql
begin;
do $$
declare v_owner uuid := '<VERIFIED_OWNER_AUTH_UUID>'::uuid;
begin
  if not exists (select 1 from auth.users
      where id=v_owner and email_confirmed_at is not null) then
    raise exception 'OWNER_ACCOUNT_NOT_VERIFIED';
  end if;
  if exists (select 1 from public.anons_studio_customer_ids
      where customer_no=1 and user_id<>v_owner) then
    raise exception 'OWNER_ID_ALREADY_ASSIGNED';
  end if;
  insert into public.anons_studio_customer_ids(user_id,customer_no)
  values(v_owner,1)
  on conflict(user_id) do update set customer_no=1;
  insert into public.anons_studio_manual_admins(user_id)
  values(v_owner) on conflict do nothing;
end $$;
commit;
```

Пользовательский интерфейс не содержит кнопки «Сделать меня владельцем». Добавление в список администраторов разрешено только привилегированному доступу к базе.

## Заказы

- Доступны **«Бизнес» 299 ₽, «Про» 499 ₽ и «Студия» 999 ₽ / 30 дней**. Технические ключи: basic, pro, studio. Цена выставляется только защищённой функцией в базе, не передаётся из интерфейса.
- «Бизнес» теперь включает три шаблона Business Brief, Business Pitch и Business Report; «Про» и «Студия» используют их и базовый платный экспорт, а дополнительные возможности этих тарифов будут разработаны на следующих этапах.
- Клиент регистрируется с подтверждением почты, видит постоянный **числовой номер** без префикса, выбирает тариф и создаёт заявку с номером AS-xxxxxx.
- Реквизиты пока не опубликованы. Клиенту нужно получить их непосредственно от проверенного владельца. Не хранить данные карты, CVV, коды и пароли в заявках.
- Клиент сообщает о переводе. Это **не доказательство поступления денег** и не включает подписку.
- Администратор видит заказ, сумму, ID клиента и почту, сверяет фактическое банковское поступление, затем вручную подтверждает. ТОЛЬКО это действие выдаёт Basic на 30 дней через защищённую RPC.
- Для того же действующего тарифа новое подтверждённое поступление продлевает доступ на 30 дней. Изменить другой активный оплаченный тариф до окончания его срока нельзя, чтобы исключить потерю уже оплаченного периода. Подключённые реальные платежи YooKassa остаются отключёнными и не смешиваются с ручными заказами.
- Подтверждение заявки и приём перевода необходимо согласовать с требованиями банка, законодательства и правилами выдачи чеков/налогообложения по месту деятельности.

## Безопасность

Ручные заказы хранятся отдельно от YooKassa, клиент может читать только свои. Нет прямых клиентских UPDATE/INSERT/DELETE для таблиц заказов, ID, администраторов и платных подписок. SECURITY DEFINER RPC имеют ограниченный набор аргументов, явную проверку UID, права EXECUTE только для authenticated. Ни один пользователь не может установить paid/approved через клиентский запрос. При необходимости администраторов можно удалить через доверенный SQL.

Для новых функций обязателен успешный GitHub Actions и публикация в **anons-studio-preview**, без развёртывания других проектов из монорепозитория.
