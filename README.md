# Hunmeng Novels · English edition · v0.6.1

Hunmeng is a static Astro + TypeScript web novel library. The default and only interface language is now **English**, including reader and editorial tools, auth errors, form validation, demo fiction, news, catalog filters, PWA metadata, structured data, covers, and social preview images.

- Genre and tag directories: `/genres/` and `/tags/`, with searchable groups, local book counts, and catalog links. The catalog supports all/any included tags plus exclusions. Vocabulary and reference notes: [docs/taxonomy.md](docs/taxonomy.md).
- 0.6.1: compact header with four navigation sections, quick title/author search and genre/tag links, a keyboard-accessible theme panel, and an avatar menu for sign-in, profile, reading settings and local sign-out. On mobile the brand/actions and navigation occupy two compact rows. Library, reading progress and preferences are preserved.
- 0.6.0: refreshed discovery pages, larger covers, early reading actions and contents links, a persistent header appearance selector, useful genre/tag defaults, shareable directory searches, and catalog search that stays responsive while chapter counts refresh.
- Production: https://dexterity-maker-hunmeng-novels-364c.twc1.net/
- Node.js 24 (minimum 22.12), `npm ci`, `npm run build`; publish `dist` on Timeweb.
- Validate: `node --test tests/*.test.mjs`, then `npm run build:demo` and `npm test` (Chromium required). Browser tests need the demo build; do not deploy it.
- Routes, novel/chapter slugs, browser storage keys, accounts, and permissions are preserved. Existing reading progress and shelves survive this release. User-entered nicknames and bios are not translated.
- Database enums and legacy column names such as `title_ru` remain unchanged for compatibility. The editorial form accepts the English title and description in those columns; `src/lib/labels.ts` provides English labels for stored statuses and glossary types. No database migration is needed.
- Reader accounts remain enabled; Google OAuth and cross-device library sync remain disabled.
- Original-fiction writing studio: `/studio/` (requires a signed-in reader account), with owner-private novels, chapter autosave (2.5 s after typing stops), character/world notes, plot outline, genres/tags and append-only manual revision snapshots. The studio never publishes a draft; public novels continue through the separate reviewed workflow. Studio tables use Supabase RLS and no public client secret. Schema and serial alignment: `backend/author-studio.sql` (applied to the connected Hunmeng Supabase project on 2026-10-27). The repository branch must be deployed to make the UI available.
- Supabase Auth email templates are configured outside this repository. This release translates the website and its confirmation/error screens; it does not change external email templates.
- Keep source permissions and human review requirements for publication. Publication announcements are generated in English. New editorial content should be supplied in English.
- English form messages are set locally and do not depend on the browser's language. Dates, numbers, sorting, and chapter plurals use English conventions. Localization tests exercise English and Russian browser locales.
- Vector cover/social sources and their PNG exports are committed. Production builds verify PNGs and do not generate images or rely on server fonts.
- 0.5.1: Cover art for *Comprehension Against the Heavens* (`public/images/comprehension-against-the-heavens.jpg`, 520×760, generated in ChatGPT from our prompt); it is also the link-preview image for the novel and its chapters.

The novel uses the placeholder cover `/images/novel-placeholder.svg` until the real cover is added; for that placeholder, link previews use `og-default.png`. # Хунмэнг · новеллы · Astro

Латиницей: **Hunmeng Novels**. Версия **0.3.1**. Мобильные улучшения — в разделе 0.3.1, оформление и профиль — в разделе 0.3.0; вход читателей — в разделе 0.2.3, редакция и развёртывание — в разделе 0.2.2.

Текущий публичный адрес: **https://dexterity-maker-hunmeng-novels-364c.twc1.net/**. До подключения hunmeng.net он используется для canonical, OG и sitemap; `SITE_URL` при сборке имеет приоритет над `site.url`.

Статический Astro-фронтенд: новеллы, главы, глоссарии и новости лежат в репозитории. Читательские аккаунты **включены** (`site.features.accounts: true`), но синхронизация **выключена** (`readerSync: false`): библиотека, настройки и прогресс сохраняются локально. Отдельный вход редакции `/admin/login/` работает по email/паролю и проверяет роль сотрудника; пользовательская регистрация не даёт редакторских полномочий. Google OAuth не включён.

В каталоге две демонстрационные истории: 3 главы «Хранителя тихого маяка» и 4 главы «Сада на краю зимы». Их тексты и авторы вымышлены; ссылки example.org — примеры. Реальные произведения допускаются только после подтверждения разрешений на перевод, публикацию и обложку.

## Запуск

Нужен Node.js 24 (или совместимый >=22.12), npm. Версия зафиксирована в `.nvmrc`.

```bash
npm ci
npm run dev
```

Откройте адрес из терминала (обычно http://localhost:4321).

```bash
npm run format    # единое форматирование исходников
npm run check     # типы Astro/TypeScript и схемы
npm run build     # проверка, HTML-сборка и аудит локальных ресурсов/ссылок
npm run preview   # просмотр готового dist, не production-сервер
npm test          # браузерные проверки desktop/mobile (после сборки)
```

В изолированном CI без TCP-сервера поддержан `STATIC_TEST=1`: файлы из dist отдаются через перехват запросов в браузере, логика приложения не подменяется. При наличии своего Chromium можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`.

Для обычных тестов один раз установите Chromium: `npx playwright install chromium`. Тестовые браузеры не входят в сайт и не нужны Timeweb для сборки.

## Что внутри

- `src/config/site.ts` — название «Хунмэнг», подпись «новеллы», латинское имя Hunmeng Novels, домен, настройки логотипа, основные цвета и названия полок.
- `public/images/` — локальные PNG-логотипы и оригинальные SVG-обложки; никаких запросов за картинками к сторонним сайтам.
- `src/content.config.ts` — четыре типизированные Astro content collections на локальных glob loaders.
- `src/content/novels/*.json` — метаданные произведений.
- `src/content/chapters/<slug>/*.md` — Markdown-главы.
- `src/content/glossaries/*.json` — словарь каждой новеллы; на странице произведения сгруппирован по типам.
- `src/lib/content.ts` — сортировка, маршруты и проверка связности данных; сборка останавливается при дубликатах глав, slug, отсутствии глоссария или главы без произведения.
- `src/lib/storage.ts` — **читательское localStorage**, валидация, версия формата, настройки и контракт `ReaderRepository` с Promise-методами для будущего сервера.
- `src/scripts/` — небольшой клиентский TypeScript без React и UI-фреймворков.
- `src/pages/` — главная, каталог, библиотека, произведения, главы и служебные страницы.
- `scripts/audit-build.mjs` — проверка локальных ссылок и отсутствие сторонних загружаемых ресурсов в HTML/CSS.
- `tests/` — браузерные проверки основных сценариев.

## Добавить новеллу

1. Придумайте постоянный уникальный slug латиницей через дефис, например `gorod-vetra`.
2. Положите локальную обложку в `public/images/gorod-vetra.webp`. Путь в метаданных начинается с `/images/`. Поддержаны SVG, WebP, PNG, JPG. Изображение должно быть вашим или разрешённым к использованию.
3. Создайте `src/content/novels/gorod-vetra.json`:

```json
{
  "slug": "gorod-vetra",
  "title": "Город ветра",
  "originalTitle": "City of Wind",
  "author": "Имя автора",
  "originalUrl": "https://example.org/original/city-of-wind",
  "cover": "/images/gorod-vetra.webp",
  "description": "Краткое описание истории длиной не менее двадцати символов.",
  "genres": ["Фэнтези", "Приключения"],
  "tags": ["Магия", "Дружба"],
  "originalStatus": "Продолжается",
  "translationStatus": "Переводится",
  "updatedAt": "2026-10-24",
  "addedAt": "2026-10-24",
  "demo": false
}
```

Дата `addedAt` определяет порядок карточек в разделе «Новые новеллы»; если поле не указано, произведение не отображается в разделе новинок, но остаётся в каталоге. Необязательное числовое поле `views` отображает произведение в рейтинге «Популярное» (только при реальных подсчитанных просмотрах, без придуманных значений).

`originalStatus`: «Продолжается», «Завершён», «Приостановлен». `translationStatus`: «Переводится», «Завершён», «Приостановлен». Даты — YYYY-MM-DD. Словари жанров/тегов каталога собираются из данных автоматически. Каталог ищет по обоим названиям, не различая регистр и е/ё. Все включённые теги обязательны; любой исключённый тег исключает книгу.

4. Создайте `src/content/glossaries/gorod-vetra.json` (пустой массив допустим):

```json
{
  "novelSlug": "gorod-vetra",
  "terms": [
    { "original": "Lin", "translation": "Линь", "type": "персонаж" },
    { "original": "Wind City", "translation": "Город ветра", "type": "место" },
    { "original": "Quiet Step", "translation": "Тихий шаг", "type": "техника" },
    { "original": "Wind Key", "translation": "Ключ ветра", "type": "предмет" }
  ]
}
```

5. Добавьте минимум одну главу, выполните `npm run build`, проверьте страницы через `npm run preview`. На сайте нет механизма получения разрешения: письменное согласие автора на перевод/публикацию и права на обложку храните отдельно. Не коммитьте частные документы в публичный репозиторий.

## Добавить главу

Создайте `src/content/chapters/gorod-vetra/glava-1.md`:

```markdown
---
novelSlug: gorod-vetra
slug: glava-1
number: 1
title: Первый ветер
publishedAt: '2026-10-24'
description: 'Глава 1. Линь впервые входит в город, где ветер помнит каждое имя.'
---

Первый абзац новой главы.

Второй абзац. Можно использовать **выделение**, _курсив_, списки и цитаты.
```

`slug` задаёт URL `/novel/gorod-vetra/glava-1/`, `number` — порядок в оглавлении. Description — 10–200 символов. Не начинайте текст с повторного H1: название главы выводит шаблон. Используйте отдельные абзацы для точного сохранения позиции. Пишите доверенный Markdown: HTML в контенте предназначен для владельца репозитория, а не для непроверенного пользовательского ввода. Любые изображения/вложения в Markdown тоже храните локально.

Обновите `updatedAt` в новелле; фактически на сайте используется более поздняя из этой даты и дат её глав. Новый файл не появится на опубликованном сайте до следующей сборки. Не меняйте опубликованные slug без настройки перенаправлений: это ломает внешние ссылки и локальный прогресс. После существенной правки текста сохранённый абзац может сместиться. Для SVG-обложки заранее добавьте `public/images/<slug>-og.png` 520×760: сборка проверяет файл, но не создаёт его.

## Читалка и локальная библиотека

Темы: «Как в системе» (по умолчанию), светлая, тёмная, сепия. Системная тема следует за `prefers-color-scheme` и обновляется при смене оформления телефона, в том числе для логотипов. Явно выбранная тема от системы не зависит. Шрифты читалки: локальные Noto Serif и Manrope с кириллицей, либо системный. Заголовки и текстовый логотип используют локальную Lora. Размер 16–32 px (по умолчанию 20 px), интервал 1.4–2.4, максимальная ширина 480–960 px (на телефоне ограничена экраном). На телефоне подписи нижней панели не меньше 13 px, элементы управления — не меньше 44×44 px. Кнопки перехода в конце главы имеют текст от 15 px и на телефоне занимают всю ширину. Панель скрывается при движении вниз и появляется при движении вверх, по тапу на текст либо круглой кнопке «Аа». Оглавление и настройки открываются в нативных диалогах: Escape закрывает окно, фокус удерживается внутри.

Позиция сохраняется по номеру абзаца и его смещению относительно экрана, дополнительно хранится доля прочитанной главы. Возврат через «Продолжить» и перезагрузка восстанавливают место после загрузки шрифтов. Прямой переход к другой главе начинает её сверху. При начале чтения книга без полки или с полкой «Прочитать позже» попадает в «Читаю». Другие полки не меняются. Прочитанная глава сохраняется автоматически; полка «Прочитано» выбирается читателем вручную, поскольку продолжение может выйти позже. Прогресс не является аналитикой: данные не отправляются владельцу сайта.

Библиотека хранится под ключом `hunmeng-novels:v1`. Данные из ключа прежних версий не переносятся. Полки: читаю, прочитать позже, прочитано, брошено. Кнопка «В библиотеку» сначала помещает книгу в «Прочитать позже», затем можно выбрать другую полку. Изменения между вкладками синхронизируются событием storage. Очистка данных браузера удаляет библиотеку и настройки; между устройствами синхронизации нет. При запрете или переполнении localStorage отображается предупреждение и используется память текущей страницы.

Для аккаунтов/БД реализуйте `ReaderRepository` через свой API, затем добавьте согласованный импорт локальных данных в аккаунт. Компоненты не должны обращаться к localStorage напрямую. Схемы контента можно оставить файловыми и после добавления аккаунтов. Админка сможет позже создавать эти файлы или заменить loader на контролируемый источник.

## Каталог и показатели произведений

Каталог поддерживает поиск по русскому/оригинальному названию, автору и тегам, категории, жанры, статусы, минимальное количество глав, включение/исключение тегов, минимальную оценку, сортировки и постраничное отображение по 24/48 карточек. Состояние фильтров и страницы отражается в URL. Клиент получает лёгкий индекс `/catalog-index.json`, не загружая тексты и списки глав в поиск. При отключённом JavaScript первая страница каталога и статические страницы `/catalog/page/2/` и далее остаются доступны.

Дополнительные необязательные поля каждой `src/content/novels/*.json`:

```json
{
  "categories": ["Сянься", "Культивация"],
  "rating": { "average": 4.5, "count": 120 },
  "views": 3200
}
```

`rating.average` — реальное агрегированное среднее в диапазоне от 1 до 5; `rating.count` — число реальных оценок (положительное целое); `views` — реальное число просмотров (неотрицательное целое). **Не задавайте вымышленных чисел**: отсутствие полей показывает «Пока нет оценок» и «Нет данных»; отсутствие рейтинга также исключает новеллу из фильтра по минимальной оценке. Текущая статическая версия НЕ считает посещения и НЕ собирает общий рейтинг самостоятельно. Для серверных счётчиков и публичных голосов потребуются API, база данных, защита от накрутки и правила приватности.

Кнопки 1–5 звёзд на странице произведения — исключительно **личная оценка читателя** в localStorage под ключом `hunmeng-personal-ratings:v1`. Она не отправляется на сервер и не изменяет публичное среднее. Нельзя объединять эти две метрики без явного интерфейса серверной части.

Для больших томов страница новеллы показывает первые 30 глав и ссылку на полное оглавление `/novel/<slug>/chapters/1/`. Оглавление разбито на статические страницы по 100 глав, ссылки работают без JavaScript. Во всплывающем меню читалки показываются только 10 соседних глав с каждой стороны текущей (максимум 21), со ссылкой на полную страницу оглавления. Это ограничивает размер HTML даже при тысячах глав; генерация множества Markdown-страниц по-прежнему выполняется при сборке, поэтому время сборки следует измерять при росте библиотеки.

## Локальные ресурсы и приватность

Все команды Astro запускаются через `scripts/astro.mjs` с `ASTRO_TELEMETRY_DISABLED=1`: телеметрия отключена и во время сборки, и при разработке. Не заменяйте npm-скрипты прямым вызовом Astro без этого флага.

В опубликованном сайте нет Google Fonts, CDN, аналитики, Cloudflare, внешних JS, API перевода и удалённых иконок. Шрифты устанавливаются из npm **во время разработки/сборки**, затем Astro помещает WOFF2 в `dist/_astro/`. Посетитель загружает всё с вашего домена. Системный шрифт тоже не требует сетевого запроса. Прямая ссылка на оригинал открывается только по действию читателя.

Для установки зависимостей Timeweb/разработчику нужен доступ к npm, а для получения проекта — к GitHub; это не runtime-зависимости читателя. `catalog.json` является локальным статическим файлом. Сам каталог, тексты, оглавления и переходы доступны без JavaScript; настройки, фильтрация и библиотека требуют JavaScript. В метатеге CSP ограничены загружаемые ресурсы своим доменом; inline допускается для сгенерированного Astro CSS и конфигурации. На production настройте также HTTP-заголовки через возможности хостинга. Не включайте сторонний CDN в панели домена.

## SEO и адрес сайта

По умолчанию sitemap, canonical и OG используют технический домен Timeweb из `src/config/site.ts`. Переменная сборки `SITE_URL` имеет приоритет. Адрес `https://hunmeng.net` в `.env.example` — пример для будущего собственного домена: не копируйте его в production до проверки DNS/HTTPS. После смены адреса нужна пересборка.

Логотип в шапке и подвале задаётся двумя путями в `src/config/site.ts`: `site.logo.light` → `/images/logo-light.png` для светлой темы и сепии, `site.logo.dark` → `/images/logo-dark.png` для тёмной. Переключение выполняет CSS по `html[data-theme]`, без фильтров цвета. Сохранённые тема, шрифт, размер, межстрочный интервал и ширина колонки применяются синхронно в head до первого отображения страницы. Ранний скрипт и основной модуль используют одинаковую проверку допустимых значений. Если localStorage недоступен, ранний скрипт ничего не меняет; CSS уже содержит исходные настройки и системную тему. Название «Хунмэнг» и подпись «новеллы» рядом с эмблемой остаются текстом. В теме «Как в системе» картинка следует за настройкой телефона. ## Новости Хунмэнг

Раздел `/news/` содержит оригинальные новости проекта: записи о релизах, объявления и, когда они существуют, сведения о розыгрышах. Три последние публикации показываются на главной. Кнопка «Просмотреть все» открывает общую ленту; там есть фильтры по категориям и постраничное отображение по 4 публикации.

Источником служит коллекция `src/content/news/*.md`. Для добавления новости создайте Markdown-файл, например `src/content/news/new-feature.md`:

```markdown
---
title: "Добавлена новая возможность"
excerpt: "Краткое правдивое описание изменения, которое увидят в ленте."
category: changelog
publishedAt: '2026-10-25'
order: 1
---

Подробности изменения...
```

Категории: `changelog` (Журнал изменений), `announcements` (Объявления), `giveaways` (Розыгрыши). Поле `order` определяет порядок публикаций с одинаковой датой. Содержимое статически создаётся при `npm run build`; отдельные URL вида `/news/new-feature/` не требуют JavaScript. Публикуйте только реально произошедшие события, не копируйте новости и тексты сторонних сайтов без прав.

Фильтрация и пагинация ленты работают в браузере и сохраняют категорию и номер страницы в URL. Без JavaScript доступны все статьи единым списком. Реакции на странице публикации — **личный выбор**, хранящийся под ключом `hunmeng-news-reactions:v1` в localStorage. Здесь нет серверных реакций, публичных голосов, фальшивых счётчиков или уведомлений. При очистке данных браузера реакции исчезают.

## Серверная архитектура и публикация переводов (следующий этап)

**Текущий статус 0.2.2:** публичная конфигурация указывает на проект Supabase `kvgnjsntumofwqhywiea`. Редакторская схема уже существует; повторно применять schema.sql к ней не нужно. Читательские аккаунты и синхронизация выключены. Конвейер запускается только при `HUNMENG_PUBLISH_ENABLED=true`; наличие кода не подтверждает настройку секретов или успешную публикацию.

### 1. Новый выделенный проект Supabase

Создайте **отдельный Supabase-проект для сайта Hunmeng Novels**. В SQL Editor этого проекта выполните целиком SQL-файл [backend/schema.sql](backend/schema.sql). В нём определены таблицы с Row Level Security: novel_staff, novel_reader_state, novel_sources, novel_terms, novel_translation_jobs и novel_publication_events.

Для новой установки включите Email/Password в Supabase Auth. Учётную запись сотрудника создаёт владелец через Supabase Dashboard, затем вручную выдаёт роль из SQL Editor, подставив проверенный ID auth.users. На `/account/` регистрации нет. Подробная инструкция 0.2.2 приведена ниже:

    insert into public.novel_staff (user_id, role)
    values ('<UUID_РЕАЛЬНОГО_ПОДТВЕРЖДЁННОГО_ПОЛЬЗОВАТЕЛЯ>', 'admin');

Роль не назначается через пользовательские JWT user_metadata. RLS ограничивает личную библиотеку владельцем, скрывает черновики от обычных пользователей и допускает редакторские операции только для пользователей novel_staff. Перед запуском дополнительно проверьте RLS с двумя тестовыми пользователями.

### 2. Переменные сборки Timeweb

Задайте при сборке Astro PUBLIC_SUPABASE_URL=https://your-novels-project.supabase.co и PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_... . Это публичный publishable key, не service_role. Не передавайте service_role или секреты в переменные с префиксом PUBLIC_. После настройки пересоберите приложение.

### 3. Аккаунты и читательская синхронизация (сейчас отключены)

При будущей явной активации `accounts: true` код `/account/` предусматривает регистрацию, вход, выход и ручную синхронизацию. Сейчас формы и синхронизация недоступны. У локального чтения сохраняется офлайн-режим. При входе библиотека из localStorage объединяется с novel_reader_state. Для прогресса выбирается позиция с более поздним updatedAt; локальные полки имеют приоритет. После изменений запускается синхронизация с небольшой задержкой.

Ограничение MVP: удаления с разных устройств и конкурирующие правки полок ещё не имеют per-item конфликтного разрешения или tombstones. Поэтому эта версия не должна считаться полноценной резервной копией, особенно при длительной работе офлайн.

### 4. Управление оригиналами, словарём, переводом и правами

/admin/: только штатные администраторы и редакторы. Администратор создаёт запись оригинала с русским названием, описанием, автором, жанрами и URL, проверяет доказательство разрешения, срок действия и отдельные флаги перевода/публикации. Редактор ведёт словарь закреплённых терминов и готовит черновики глав.

Для утверждения администратор должен провести **человеческую вычитку** и оставить заметки длиной от 20 символов. База проверяет лицензию, тексты, описание, запрещённые заглушки и наличие переводов терминов словаря. Утверждённая запись не может незаметно менять содержимое, а опубликованная недоступна для клиентского редактирования. QA здесь базовый, а не гарантия литературного качества.

### 5. Автоматическая публикация только одобренного и разрешённого

Workflow .github/workflows/publish-approved.yml каждые 6 часов или при ручном запуске проверяет только статус approved. Скрипт scripts/publish-approved.mjs повторно проверяет разрешения/срок/человеческое одобрение/термины, записывает новые Markdown-главы и при необходимости метаданные произведения, коммитит их в main, а **только после успешного push** отмечает работы опубликованными. Существующие главы не перезаписываются.

**Публикация выключена по умолчанию.** Для включения в GitHub Actions добавьте Secrets SUPABASE_URL и SUPABASE_SERVICE_ROLE_KEY (только серверный service-role JWT), а также Variables HUNMENG_PUBLISH_ENABLED со значением true. Эти данные **нельзя** коммитить или передавать в браузер. Если секретов или разрешений нет, пользовательские переводы не публикуются. Учтите защиту ветки main: GitHub Actions должен иметь право на push, либо настройте защищённый процесс через PR.

Внешний n8n может импортировать черновики через Supabase REST с авторизованной учётной записью редактора. Для генерации переводов AI, получения оригиналов и проверки прав потребуется отдельная легальная интеграция: в текущем этапе автоперевод не запускается и не скачивает тексты без разрешений.

### 6. Что ещё требует реальной интеграционной проверки

После настройки отдельного Supabase-проекта протестируйте: вход/подтверждение email, две учётные записи и RLS, синхронизацию на двух устройствах, истёкшую или отозванную лицензию, нарушения словаря, запрет небезопасного HTML, права editor/admin, повторный запуск workflow и ошибки GitHub push. Astro и Playwright проверяют только локальную статическую сборку, не рабочую базу и не реальный SMTP.

## Версия 0.1.4 — локальная библиотека читателей

Для аудитории в России регистрация и авторизация **временно выключены по умолчанию** флагом `site.features.accounts: false` в `src/config/site.ts`. До отдельного решения вопросов доступности Supabase из России и требований к локализации персональных данных не включайте читательские аккаунты. Это техническая мера ограничения обработки данных, а не юридическое заключение.

При `accounts: false`:
- ссылки «Аккаунт» скрыты в навигации, футере и библиотеке;
- `/account/` не показывает форм регистрации, входа по email/паролю или Google; по прямому URL отображается только сообщение о временной недоступности;
- фоновая синхронизация и запросы к Supabase для читателей не запускаются;
- полки, настройки и позиции чтения сохраняются **исключительно в localStorage**; синхронизации между устройствами нет.

Страница `/admin/`, проверка ролей, миграция Supabase и автоматический конвейер публикации остаются без изменений и предназначены только для владельца. Читательский флаг не заменяет права доступа к админке: её по-прежнему защищает Auth/RLS. Для повторного включения `accounts: true` необходимо предварительно решить организационные и правовые требования, пересобрать сайт и проверить регистрацию и синхронизацию.

На телефонах (ширина экрана до 760 px) текст главы выровнен влево и применяет `hyphens: manual` вместе с `-webkit-hyphens: manual`; автоматические переносы отключены. На широких экранах оформление читалки не менялось.

## Версия 0.2.2 — вход владельца и проверка выпуска

### Вход редакции

1. Откройте `/admin/login/` и введите email и пароль **уже созданного** сотрудника. Ссылок регистрации и Google-входа здесь нет.
2. Supabase Auth проверяет пароль, `/auth/v1/user` проверяет сессию, затем `novel_staff` возвращает роль текущего пользователя. Допустимы только `admin` и `editor`. Неподходящая роль завершает сессию; редакторские таблицы при этом не запрашиваются.
3. После проверки открывается только `/admin/`. Параметры `next`/`redirect`, OAuth-коды и токены из URL не используются. На административных страницах query/hash очищаются, referrer отключён, установлен `noindex`; страницы не входят в sitemap.
4. Кнопка «Выйти из редакции» сначала удаляет сессию текущей вкладки, затем отзывает её через Supabase (`scope=local`). Если сервер недоступен, панель закрывается и показывает предупреждение о неподтверждённом отзыве. Это не выход из других устройств.

Сессия редакции хранится в **sessionStorage** под ключом `hunmeng-novels:admin-session:v1` и не импортируется из старой читательской сессии. После закрытия вкладки требуется новый вход. В новой вкладке браузер может клонировать sessionStorage при открытии из текущей — используйте выход на общем устройстве. Токены не попадают в URL, логи или исходники; в статическую сборку входит только публичный publishable key. В статическом frontend невозможно использовать HttpOnly-сессию без отдельного сервера: защита данных обеспечивается Supabase Auth/RLS; XSS на том же origin остаётся существенным риском.

Перед запросом просроченный access token обновляется. При 401 сессия удаляется, при 403 панель закрывается. Роль повторно проверяется при возвращении во вкладку и раз в минуту; RLS проверяет каждый запрос независимо от интерфейса. Редактор не видит создание источников и подтверждение прав, администратор видит все функции. HTML оболочки админки публичен как часть статики и не содержит закрытых данных.

## 0.3.1 — мобильная читаемость и продолжение чтения

Увеличены подписи жанров, статусов и дат до 14 px, области нажатия навигации и основных текстовых ссылок — минимум 44 px. Поле поиска на главной уточняет поиск по названию или автору. На планшетной ширине главы и новости располагаются последовательно, на телефоне сохраняется одна колонка. Масштаб браузера и возможность увеличения текста не блокируются.

Мобильный каталог оставляет поиск видимым, а остальные параметры прячет в нативный `<details>` «Фильтры и сортировка». Счётчик показывает количество активных фильтров даже в свёрнутом состоянии. Сброс работает после закрытия панели; значения сохраняются в URL, изменение ширины не сбрасывает подбор. На компьютере фильтры открыты. Без JavaScript список новелл и раскрытие панели доступны, интерактивный поиск требует JavaScript.

Модуль `src/lib/reading-action.ts` выбирает единое действие для главной, новеллы и библиотеки. После отображаемых 100% главы (ratio ≥ 0.995, как при округлении индикатора читалки) предлагается следующая опубликованная глава без восстановления позиции предыдущей. На 98–99% прежняя позиция продолжает восстанавливаться. После последней опубликованной главы книга убирается из «Продолжить чтение», а в библиотеке появляется «Все опубликованные главы прочитаны» и возможность читать сначала. Это не объявляет перевод завершённым. Если добавят новую главу, продолжение появится снова. Полки автоматически не меняются; «Прочитано» и «Брошено» исключены из блока продолжения.

Если на телефоне видна целая двухколоночная страница с очень мелкими буквами, проверьте режим «Версия для ПК» в браузере. Он может заставлять браузер использовать широкий виртуальный экран и уменьшать весь сайт. Сайт не должен принудительно отключать этот выбор пользователя; для мобильной вёрстки выключите данный режим. Возможность масштабировать страницу сохраняется.

Проверки: `npm run build`, `npm test`, `node --test tests/*.test.mjs`. Дополнены сценарии сворачивания/сброса фильтров, изменения ширины, конца главы, новых глав, сохранения полок и минимальных размеров текста/ссылок. Авторизация, RLS и Supabase в этом выпуске не меняются.


### Original serial releases

All published novel chapter bodies must contain 4,000–8,500 Unicode characters (spaces and paragraph breaks included; frontmatter excluded). This rule is checked by `scripts/validate-serials.mjs` for every published novel.

`The Latency of Tomorrow` is planned as 247 English chapters, each 4,000–8,500 Unicode characters including spaces (body only, LF paragraph breaks, trimmed at both ends). The chapter count changes as writing continues; see src/content/chapters/the-latency-of-tomorrow (84 chapters at the 2026-10-27 review). `npm run build` validates every opening chapter against the agreed plan and rejects public manuscript files beyond chapter 85. Demo novels remain test fixtures only.

The generated cover is `public/images/the-latency-of-tomorrow.jpg`; its creation brief is in `editorial/the-latency-of-tomorrow-cover.md`.

`backend/serial-releases.sql` installs a separate, RLS-protected manuscript store and an inactive edition. Never put chapters 86–247 in Git, static JSON, HTML, or client bundles. Import their complete plain-prose bodies privately into `serial_chapters`. Public `anon` and signed-in `authenticated` requests have the same read-only release policy; neither can write or change the schedule. No service key is used by the browser.

Before activation, finish and validate all 247 bodies, import them privately, deploy chapters 1–85, verify the live initial chapters and all scheduled shells, and then set `serial_editions.launch_at` to the actual launch instant through an authorized backend operation. The database refuses activation of an incomplete manuscript and makes the schedule immutable afterward. Do not backdate it. The current edition has **not** been activated.

Chapters 1–85 are available at launch. Chapter 86 opens at 12:00 Europe/Moscow on the following calendar day; chapter 247 opens at noon on day 162. Postgres evaluates availability on each request, so opening a chapter does not depend on a delayed build, cron job, visitor clock, or JavaScript hiding its text. The release contents page and scheduled reader fetch only rows allowed by RLS, with no browser caching. An open page checks again every 15 seconds and on return to the tab. Network latency can delay display; access is determined by the server boundary.

`playwright.serial.config.ts` tests the production novel and scheduled reader. The normal browser suite continues to use `npm run build:demo`; it is never a deployable production build. Scheduled shells carry no chapter body or article structured data and are excluded from the sitemap.
