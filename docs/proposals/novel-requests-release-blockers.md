# Request intake: release blockers

Status: **not ready for production**. The schema has been tested with fictitious PGlite fixtures and a disposable PostgreSQL 17.11 instance in GitHub Actions. The HTTP handler is disconnected; a server-only creation prototype exists but is not wired to authentication or a route.

## Schema review

1. Direct SELECT for service_role on private rights evidence was removed. The external PGlite 18.6 report confirmed the role had neither schema USAGE nor table SELECT after the change. Verify actual Supabase role inheritance and privileges separately.
2. The request constraint trigger was corrected to use new.id. The external PGlite report confirmed request insertion and update commit successfully, while an invalid conversion fails at COMMIT.
3. The PGlite report confirmed user deletion was blocked by append-only audit triggers. The current draft proposes a narrow exception for the foreign-key ON DELETE SET NULL action, preserving the pseudonymous reference and every other field. The external PGlite 18.6 report for commit d96d2d8 verified both audit tables, normal update/delete denial, manual ID clearing denial, rollback and retention of non-ID fields. Real Supabase behavior is unverified. Trigger nesting is not a security boundary against privileged roles able to alter database objects.
4. PGlite tests on commit 8aacf960 confirmed that deferred draft checks use the final row. Those tests also confirmed that changing only an external source work_id could commit an inconsistent link. The new candidate adds deferred rechecks on source and work updates and checks linked drafts when requests change. The external PGlite report for commit 9c6e002 confirmed the intended sequential cases.
5. PostgreSQL 17.11 in GitHub Actions reproduced a write-skew race: an external-source reassignment and concurrent request insertion both committed an inconsistent link. The source-specific transaction advisory lock passed the reproduced race on PostgreSQL 17.11. A second race between a work update and draft creation was reproduced and the work-specific lock passed that case. Both tests ran on commit 46d49387 (GitHub Actions run 40811396793). Other interleavings, deadlocks, retries, isolation levels and lock ordering remain unproven. A non-public SQL creation prototype was tested against PostgreSQL 17.11 for atomic replay, conflicting keys, active-source deduplication, per-user creation quotas, parallel submissions and rollback (commit 7e3538fd; Actions run 40811821421). It assumes a trusted caller and does not verify caller identity, derive requester refs, implement HTTP/IP throttling, store match evidence or connect to the handler. Moderation, conversion and real authentication remain unimplemented. RLS, role isolation and concurrent operations require real Supabase tests. A keyed HMAC requester reference is implemented in the isolated handler; secure key provisioning, rotation and migration still need a reviewed deployment design.

## Isolation

The connected Supabase project has no development branch; Supabase reported branch creation requires a Pro plan. A second free project could not be created because the owner's free-project quota is exhausted. No Supabase or production database changes were made. PGlite 18.6 is useful for preliminary tests but cannot establish compatibility with production PostgreSQL 17 or actual Supabase services.

Do not apply the draft or deploy the feature until the missing functions and security controls exist and the final design passes an isolated environment's tests.
