# Manual Pages deployment — draft, not enabled

This is a reviewable proposal, not an active deployment path. It does not run on push or pull request. GitHub dispatch requires the workflow file to be on the default branch. The draft is hard-limited to commit `3c3aad448c1b28e96a4a7bb1ecbcb941de467986` so it cannot publish an arbitrary revision. The current Cloudflare Pages project was directly uploaded, and its latest deployment has no commit hash. Before any deployment recheck that the live deployment has not changed since the verified report, and compare production configuration and content. The last verified production deployment was `1b77e383-5550-47bd-a5ff-982e402430fa`.

The workflow builds and tests the approved revision, then builds production with `SITE_URL=https://hunmeng-novel.ru` and uploads to the existing Pages project. The account ID and a Pages Edit API token are expected as GitHub Actions secrets, configured by the owner directly in GitHub; never put their values in the repository or chat. Pages Edit may cover other Pages projects in the same account; review actual token scope before creating it. The GitHub environment `pages-production` is only a label unless its protection rules are configured; creating the workflow does not configure an approval gate.

Before enabling, owner approval is needed for the deployment workflow, credentials and any changes to GitHub main. Review existing Timeweb deployment: merging into main triggers `.github/workflows/check.yml` and may deploy Timeweb. Do not activate this workflow until that effect is resolved and the production environment, secrets and rollback procedure are verified. Before publishing, verify the current deployment again and record the prior deployment ID for rollback. Run once only after CI and an explicit production authorization. Do not label this as a working deployment until it is actually tested; no secret, environment, workflow run, or Cloudflare setting has been created by this proposal.
